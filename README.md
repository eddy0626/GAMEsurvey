# 플레이테스트 리포트 자동화

2026 충북 인디게임 플레이테스트 — 구글 폼 응답에서 리포트를 자동 생성하는 Apps Script 프로젝트.

인디게임 5종을 교육 수강생 14명 + 전문가 2명이 각각 플레이하고 구글 폼에 답한다.
게임 5 × 응답자 16 = 80건이 게임별 구글 시트 5개에 쌓인다.
그 응답으로 **개별 응답 카드 80건 + 게임별 종합 리포트 5건 + 현황 대시보드 1개**를
시트 메뉴 버튼 하나로 만드는 것이 목표다.

---

## 구조 — 둘로 나눠 만든다

| | 어디서 | 무엇을 | 언제 |
|---|---|---|---|
| **현황 대시보드** | 구글 시트 (`src/*.gs`) | 응답률 · 진행 불가 버그 · 미제출자 · 이슈 플래그 | 테스트 **진행 중** 실시간 |
| **문서 생성** | 로컬 파이썬 (`py/`, `run.py`) | 개별 카드 80건 + 종합 리포트 5건 (docx) | 테스트 **마감 후** 일괄 |

설계안이 이 둘을 나눠 놨다 — *"응답 중에는 시트 대시보드로 현황만 보고, 문서는 평균이 확정된 마감 후에 한 번에 만듭니다."*

문서를 파이썬으로 만드는 이유는 세 가지다.
목표 리포트 15페이지의 디자인이 `참조/gen_report.py` 에 **이미 완성돼 있어** 그대로 재사용할 수 있고,
부록 A·B·C 처럼 행 수가 응답마다 달라지는 표는 구글 문서 템플릿의 `replaceText` 로는 만들 수 없으며,
구글 권한 승인 · 6분 실행 제한 · 템플릿 수작업 없이 바로 돌릴 수 있기 때문이다.

집계 규칙은 양쪽이 같다. 두 구현 모두 수작업 리포트의 수치를 그대로 재현하는지 검사받는다.

| 단계 | 상태 |
|---|---|
| 집계 · 지표 · 이슈 플래그 (양쪽 공통 규칙) | **완료 · 검증 448개** |
| 응답 현황 대시보드 (시트) | **완료** |
| 개별 응답 카드 80건 (docx) | **완료** |
| 게임별 종합 리포트 5건 (docx) | **완료** |
| PDF 변환 | 미착수 — 지금은 Word 에서 내보내기 |
| 이슈 플래그 임계값 조정 | 실제 응답을 받은 뒤 |

## 리포트 만들기

```bash
pip install python-docx matplotlib openpyxl
python run.py --dummy      # 더미 응답을 만들고 전체 생성 (파이프라인 시험용)
python run.py              # data/응답/ 의 CSV 를 읽어 전체 생성
python run.py --game G01   # 한 게임만
```

**입력**

```
data/응답/01_미스트월드.csv        ← 응답 시트를 CSV 로 내려받아 여기 둔다
data/응답/02_….csv                  파일명 앞 두 자리가 폼 번호다
   …
data/명부.csv                      이름 · ID · 유형(교육생/전문가) · 비고
```

구글 시트에서 `파일 → 다운로드 → 쉼표로 구분된 값(.csv)` 으로 받으면 된다.
명부에 없는 이름이 응답에 나오면 다음 ID 를 자동 발급하고 `유형: 미상` 으로 명부에 덧붙인다.
같은 사람이 5개 게임을 모두 플레이하므로 **ID 는 사람 단위로 한 번만 부여된다.**

**출력**

```
out/<게임명>/<게임명>_플레이테스트_결과리포트.docx      12~15p · 표 20~40개 · 차트 3개
out/<게임명>/개별카드/「게임명」_P01_응답카드.docx       1~2p · 육각 차트 1개
```

85건 생성에 약 22초. 실명은 어떤 산출물에도 들어가지 않는다.

```

├─ run.py                   ← 리포트 생성 진입점

│   ├─ ingest.py             CSV/XLSX 읽기 · 헤더 매핑 · 응답 파싱
│   ├─ aggregate.py          지표 · 문항 집계 · 세그먼트 · 이슈 플래그
│   ├─ charts.py             레이더(1·2계열) · 막대 · 퍼널 PNG
│   ├─ docxkit.py            docx 저수준 헬퍼 (참조/gen_report.py 에서 가져옴)
│   ├─ report.py             종합 리포트
│   ├─ card.py               개별 응답 카드

│   ├─ kor.py                조사 처리 · 말줄임

├─ src/                     ← clasp 가 올리는 폴더 (시트 대시보드)
│   ├─ appsscript.json       매니페스트 (권한 · 시간대)
│   ├─ Config.gs             ★ 설정 단일 원본. 고칠 일이 있으면 여기만 고친다
│   ├─ Aggregate.gs          응답 통합 · 지표 계산 · 이슈 플래그 판정
│   ├─ Chart.gs              레이더 차트 생성 및 PNG 추출
│   ├─ Dashboard.gs          현황 대시보드
│   └─ Code.gs               메뉴 · 설정 확인
├─ test/                    ← Node 로 돌리는 검증 (구글 계정 없이 돌아간다)
│   ├─ syntax.js             문법 · 함수 이름 중복 검사
│   ├─ run.js                수작업 리포트와 수치 대조 (184개 항목)
│   ├─ edge.js               응답 2건 · 문항 변경 등 깨지기 쉬운 상황 (59개 항목)
│   └─ fixture_mistworld.json  미스트월드 15명 응답을 시트 모양으로 옮긴 것
├─ tools/
│   ├─ make_fixture.py       참조 데이터 → 미스트월드 픽스처
│   ├─ make_headers.py       설문 원본 → 5개 폼 헤더 재현 (Config 검증용)
│   └─ 일회용_구세트_폐기.gs   옛 폼 · 응답 시트를 휴지통으로 (편집기에 붙여 넣는 스니펫)
└─ 참조/                     설계안 · 목표 리포트 · 설문 원본 등
```

> **설문 원본은 `참조/survey_data.py` 가 아니라 `gamecowork/플레이테스트_설문_생성기/survey_data.py` 다.**
> `참조/` 는 검증용 사본이다. 개발사가 문항을 바꿔 오면 원본을 고치고
> 폼을 다시 만든 뒤, 사본을 갱신하고 `npm run fixture && npm test` 를 돌린다.

## 최초 설치 (한 번만)

### 1. 마스터 집계 시트 만들기

구글 드라이브에서 **새 스프레드시트**를 만들고 이름을 `2026 플레이테스트 마스터`로 한다.
스크립트는 이 시트에 붙는다. 게임별 응답 시트 5개는 **읽기만 하고 절대 건드리지 않는다.**

> 담당자가 바뀔 것에 대비해 개인 계정보다 **기관 공용 계정이나 공유 드라이브**에 두는 편이 좋다.
> 스크립트와 만들어지는 문서가 전부 만든 사람 계정에 귀속되기 때문이다.

### 2. 코드 올리기

**clasp 를 쓰는 경우 (권장)**

```bash
npm install -g @google/clasp
clasp login
```

마스터 시트에서 `확장 프로그램 → Apps Script` 를 열고 `프로젝트 설정`에서 **스크립트 ID**를 복사한다.

```bash
cp .clasp.json.example .clasp.json      # 그리고 scriptId 를 채운다
clasp push
```

`.clasp.json` 은 `.gitignore` 에 있다. 스크립트 ID 는 커밋하지 않는다.

**수동으로 붙여 넣는 경우**

Apps Script 편집기에서 파일을 하나씩 만들고 `src/` 의 내용을 붙여 넣는다.
파일 이름은 그대로 쓴다 (`Config`, `Aggregate`, `Chart`, `Dashboard`, `Code`).
`appsscript.json` 은 `프로젝트 설정 → "appsscript.json" 매니페스트 파일 표시` 를 켜야 보인다.

### 3. Config.gs 확인

`GAMES` 의 `응답시트ID` 5개는 **이미 채워져 있다** (2026-08-15 확인분).
응답 시트를 다시 만들었으면 URL 에서 뽑아 갈아 끼운다.

```
https://docs.google.com/spreadsheets/d/  1AbC...XyZ  /edit#gid=0
                                         └─ 이 부분 ─┘
```

`npm run test:config` 로 5개 폼 전부에 대해 매핑이 맞는지 구글 계정 없이 확인할 수 있다.

### 4. 첫 실행과 권한 승인

시트를 새로고침하면 상단에 **[플레이테스트]** 메뉴가 생긴다.
`설정 확인` 을 먼저 눌러 본다. 처음 실행하면 권한 승인 창이 뜬다.

> 권한 검토 → 계정 선택 → **"Google에서 확인하지 않은 앱"** 경고 →
> **고급** → **프로젝트 이름(안전하지 않음)으로 이동** → **허용**

최초 1회만 나온다.

### 5. `_명부` 채우기

`설정 확인` 을 돌리면 `_명부` 시트가 자동으로 만들어진다 (숨김 상태 — 시트 탭 우클릭 → 숨기기 해제).

| 이름 | ID | 유형 | 비고 |
|---|---|---|---|
| 홍길동 | P01 | 교육생 | |
| 김철수 | P02 | 전문가 | |

- **이름**은 응답자가 폼에 적은 이름과 똑같이 적는다 (공백은 무시하고 대조한다).
- **ID**는 비워 두면 실행할 때 자동으로 발급된다.
- **유형**은 `교육생` 또는 `전문가`.
- 명부에 없는 이름이 응답에 나오면 자동으로 새 ID 를 발급해 명부에 추가하고 유형을 `미상` 으로 둔다.

> 이 시트에만 실명이 있다. **시트 탭 우클릭 → 시트 보호** 로 접근을 제한하기를 권한다.
> 카드 · 리포트 · PDF 에는 P01 같은 ID 만 나간다.

## 매 테스트 때 하는 일

1. **테스트 진행 중** — [플레이테스트] → `집계 새로고침` 을 가끔 누른다.
   `대시보드` 탭에서 응답 현황과 **진행 불가 버그 신고**를 확인한다.
   진행 불가 버그는 테스트 중에 바로 움직여야 하는 유일한 항목이다.
2. **마감 후** — `집계 새로고침` 을 한 번 더 눌러 최종 수치를 확정한다.
3. `개별 카드 생성` → `종합 리포트 생성` → `PDF 일괄 변환` (Phase 3~5 완료 후)
4. `_플래그` 탭에서 이슈 후보를 훑고, 리포트 3장에 올릴 것을 고른다.
   **권고 문장은 담당자가 쓴다.** 자동으로 만들지 않는다.

> **문서는 왜 마감 후에 만드나** — 개별 카드에 '전체 평균 대비 내 점수' 차트가 들어간다.
> 응답이 들어올 때마다 만들면 첫 응답자의 평균은 자기 자신이고 뒤로 갈수록 기준선이 달라진다.
> 같은 테스트인데 응답자마다 다른 잣대로 그려진 차트가 나가는 셈이라, 평균이 확정된 뒤에 한 번에 만든다.

## 무엇이 바뀌면 어디를 고치나

전부 `src/Config.gs` 한 파일 안에 있다.

| 바뀐 것 | 고칠 곳 |
|---|---|
| 게임이 추가·삭제됨 | `GAMES` 에 한 줄 추가 · `게임_코어장르` · `게임_기본문항유형` |
| 응답 시트를 다시 만듦 | `GAMES` 의 `응답시트ID` |
| **공통 문항 문구가 바뀜** | `공통문항` 의 해당 키 배열 **맨 앞에** 새 문구를 추가한다. 옛 문구를 남겨 두면 과거 응답 시트도 계속 읽힌다 |
| 게임 고유 문항이 바뀜 | 아래 표 참고 |
| 플래그가 너무 많이/적게 뜸 | `임계값` |
| 드라이브 구조가 바뀜 | `드라이브` · `템플릿` |

게임 고유 문항은 유형에 따라 적을 곳이 다르다. **문항 텍스트는 번호 접두사 없이 폼에 적힌 그대로** 쓴다.

| 문항 유형 | 적을 곳 | 안 적으면 |
|---|---|---|
| 객관식 (나쁜 답이 있는 것) | `게임_부정선택지` | 그 문항으로는 플래그가 안 뜬다 |
| 체크박스 (복수 선택) | `체크박스문항` | 쉼표로 안 쪼개져 `"전투, 탐색"` 이 통째로 한 선택지가 된다 |
| 선형배율 (1~5점 · 0~10점) | `게임_선형배율문항` | 평균 대신 인원 많은 순 빈도표가 나오고 평균 기반 플래그가 안 뜬다 |
| 튜토리얼 이해도 | `게임_튜토리얼문항` | 튜토리얼 전용 규칙(Critical)을 건너뛴다 |
| 고유 문항이 전부 서술형인 게임 | `게임_기본문항유형` 을 `'서술형'` 으로 | 응답자가 '없음' 을 많이 적으면 객관식으로 오인해 부록 B 에서 서술이 사라진다 |

적지 않은 문항은 응답 내용을 보고 객관식/서술형을 자동으로 판별한다.
판별 결과는 **`설정 확인` 의 '문항 유형' 줄에 전부 나열**되니 눈으로 확인하고,
틀린 것만 `게임_문항유형` 에 적어 덮어쓰면 된다.

고친 뒤에는 반드시 **`설정 확인`** 을 돌린다.
Config 에 적은 문항 텍스트가 실제 시트 헤더에 있는지까지 대조해서, 오타가 있으면 어느 문항인지 짚어 준다.

> **문항 번호는 신경 쓰지 않아도 된다.** 구글 폼은 문항 제목 앞에 연속번호를 붙이는데
> (`17. 재미 — …`), 게임 고유 문항 개수가 폼마다 달라(10/10/13/5/16) 같은 공통 문항이라도
> 번호가 다르다. 코드가 번호를 떼고 본문만 비교한다. 열 위치도 하드코딩하지 않는다.

## 로컬 검증

구글 계정 없이 Node 로 집계 로직을 검증할 수 있다. `.gs` 는 순수 자바스크립트라 그대로 돌아간다.

```bash
npm test
```

- `test/syntax.js` — `clasp push` 전에 문법 오류와 함수 이름 중복을 잡는다.
- `test/config.js` (81개) — **5개 폼 전부**에 대해 `Config.gs` 를 검증한다.
  응답 시트 ID 형식, 총 열 수(33/33/36/30/40), 공통 문항 23개가 폼마다 다른 번호에도 전부 매핑되는지,
  6축이 연속된 열에 순서대로 있는지, **Config 에 손으로 옮겨 적은 문항 텍스트와 선택지 문구가 설문 원본에 실재하는지**,

## 자주 나는 오류

| 증상 | 원인과 대처 |
|---|---|
| `설정 확인` 에 **"응답시트ID 가 비어 있습니다"** | `Config.gs` 의 `GAMES` 를 채운다 |
| **"못 찾은 공통 문항"** 이 뜬다 | 폼에서 문항 문구를 고친 것이다. `공통문항` 의 해당 키 배열 맨 앞에 새 문구를 추가한다. `점검 도구 → 헤더 매핑 표 보기` 로 실제 헤더를 볼 수 있다 |
| **"Config 에 적힌 문항을 못 찾았습니다"** | `게임_부정선택지` 등에 적은 문항 텍스트에 오타가 있거나 문항이 바뀐 것이다. 메시지에 어느 문항인지 나온다 |
| 6축 평균이 비어 있다 | 선형배율 문항이 빈 응답이거나, 6축 문항 문구가 바뀌어 매핑이 끊긴 것이다 |
| 같은 사람이 여러 ID 로 잡힌다 | 폼에 적은 이름이 명부와 다른 것이다. 공백은 무시하지만 오탈자는 못 잡는다 |
| 동명이인이 있다 | `설정 확인` 이 오류로 잡아 준다. 명부의 이름 뒤에 구분자를 붙이고 폼 응답도 맞춘다 |
| 실행이 6분에서 끊긴다 | Phase 5 의 배치 처리가 붙기 전이다. 붙은 뒤에는 중단돼도 이어서 실행된다 |
| 레이더 차트가 이상하다 | `점검 도구 → 레이더 차트 미리보기` 로 이미지 3장을 드라이브에 저장해 눈으로 본다. 직전 응답자 그래프가 다시 나오면 `Config.gs` 의 `차트.재사용` 을 `false` 로 바꾼다 |
| 차트 축이 0~5 로 안 잡힌다 | 시트 레이더 차트는 축 옵션 지원이 완전하지 않다. `차트.고해상도URL사용` 을 `true` 로 바꾸면 시트에 보이는 그대로 내보낸다. 단 `appsscript.json` 에 `https://www.googleapis.com/auth/script.external_request` 스코프를 추가해야 한다 |

## 지키는 원칙

- **응답 시트는 읽기만 한다.** 집계 결과는 마스터 시트의 `_집계_*` 탭에만 쓴다.
- **외부 API 를 부르지 않는다.** 차트도 구글 시트 기본 레이더 차트로 만든다.
- **열 위치를 하드코딩하지 않는다.** 헤더 텍스트로 찾는다.
- **실명은 `_명부` 와 대시보드 미제출자 명단에만 있다.** 나가는 산출물에는 P01 형식 ID 만 쓴다.
- **3장 핵심 발견의 권고 문장은 자동 생성하지 않는다.** 규칙은 이슈 *후보*를 뽑고 근거 인용을 붙일 뿐이다.
